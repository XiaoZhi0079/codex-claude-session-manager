Codex & Claude Code Session Manager

指标与会话状态说明

这些数字来自工具合并扫描的 rollout、SQLite、旧索引和备份记录。

会话总计
本工具识别出的不同会话数量。它不仅包含 Codex 当前能显示的会话，也可能包含归档、仅备份或只剩元数据的记录。
Codex 可见
同时存在 rollout 正文、SQLite 线程记录，并且 SQLite 中的 model_provider 与当前供应商一致。通常能直接出现在 Codex 会话列表中。
Codex 隐藏
正文仍然存在，但缺少可用索引，或供应商信息与当前配置不一致。本工具可以读取，Codex 当前会话列表却可能不显示。

会话卡片中可能出现的其他状态

仅备份
当前 sessions 或 archived_sessions 中没有正文，只在 CCSwitch 或本工具的备份中找到。它不计入“Codex 隐藏”。
仅 SQLite
数据库里还有标题或索引记录，但 rollout 正文已经不存在。没有匹配备份时无法继续阅读原对话。
可恢复
正文当前缺失，但工具找到了会话 ID 一致的会话备份，可以通过备份管理恢复。

轮次状态与错误删除边界

正常完成
rollout 出现 task_complete 且没有错误。
错误 / 中止
task_complete.error 表示错误，turn_aborted.reason 表示中止；如果这些事件在 rollout 中，它们就是正式对话正文的一部分。
可删除的孤立错误
只有 SQLite 的 thread_turns.error_json 有失败记录、rollout 却没有相同 turn_id 时，才可单独删除。它是分页历史残留，不修改正式对话。
不可单独删除的错误
rollout 中已有的错误不能只清空错误字段；如需删除，必须删除完整轮次或从该轮开始截断，这会影响 Codex 续聊上下文。

Codex 全量会话可见性修复

把可恢复会话的供应商元数据统一到当前 model_provider；这是兼容性工具，不是日常维护功能。

运行中的 Codex

无法自动处理
-
能力边界：修复只调整 rollout 与 SQLite 中的供应商元数据，使会话有机会重新出现在列表中；不会转换或解密历史中的 encrypted_content，因此不保证跨供应商续聊成功。执行前会创建可回退的系统安全备份。
以后回退时：只把本次确实修改过的供应商字段改回，不用旧数据库或旧 rollout 覆盖当前数据。修复后新增的会话、后来追加的消息和其他字段都会保留；若目标会话已删除、供应商又被改过或路径不再安全，工具会报告冲突并拒绝整批回退。由本次修复补回的缺失 rollout 不会被删除，以免丢失后来消息。

导入并继续对话的硬性条件

            
    
              
  • 项目必须单独迁移：迁移包不包含源码；目标目录的有效文件内容必须与导出时一致。
    • 
              
  • 必须映射项目目录：旧电脑记录的每个项目路径，都要选择新电脑上的对应目录并通过指纹校验。
    • 
              
  • 会话 ID 不能冲突：同 ID、同正文会跳过或补建索引；同 ID、不同正文会硬性拒绝，绝不覆盖。
    • 
              
  • 目标 Codex 必须已经初始化：新电脑需要先安装并至少启动一次 Codex，以生成当前版本的状态数据库。
    • 
              
  • 应用导入前必须完全退出 Codex：否则运行中的 Codex 可能把旧状态重新写回。
    •
