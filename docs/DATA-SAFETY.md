# 数据安全、回滚与撤销

## 写入原则

所有写操作遵循四项原则：服务端预览、用户确认、写前恢复点、写后验证。浏览器传来的路径、计划和哈希不能单独授权写入；服务端会重新限定备份根目录、目标文件名和当前状态。

Claude Code 的读取边界保持封闭：外置工具结果即使在 JSONL 中保存绝对路径，也只会按文件名解析到当前 `sessionId/tool-results` 目录；不会跟随任意路径读取其他文件。子代理同样只从当前会话的 `subagents` 目录发现。

备份内容预览同样只接受服务端枚举出的 `backupId` 和清单内的 `sessionId`。服务端重新校验备份根目录、清单路径和会话身份后才解析正文；浏览器不能提交任意本地文件路径。自动检测只重新读取备份清单和恢复目标状态，不执行恢复、合并或其他写入。

Claude 删除只接受已扫描到的 UUID 会话，并把主 JSONL、会话侧边目录、tasks、file-history、session-env 和对应索引条目作为一个数据包。服务端重新验证路径、符号链接、逐文件指纹和预览令牌；备份复制后再次校验指纹，成功后才删除源数据。恢复清单中的路径必须与会话 ID 和项目键严格匹配，不能借清单写入 `.claude` 下的任意文件。

## 各操作保护

| 操作 | 并发保护 | 写前保护 | 失败恢复 | 一键撤销 |
|---|---|---|---|---|
| 消息编辑 | 目标 writer lock、rollout SHA-256 | rollout 与分页历史备份 | 写后解析失败时恢复原正文；投影由 Codex 重建 | 是，恢复编辑前 rollout |
| 从所选轮开始清理 | 目标 writer lock、rollout SHA-256 | rollout 与分页历史备份 | 写后解析失败时恢复原正文；投影由 Codex 重建 | 是 |
| 只删除所选轮 | 目标 writer lock、rollout SHA-256 | rollout 与分页历史备份 | 写后解析失败时恢复原正文；投影由 Codex 重建 | 是 |
| 恢复某个 rollout 备份 | 目标 writer lock、当前 rollout SHA-256 | 恢复前 rollout 与分页历史快照 | 失败时恢复调用前正文；投影由 Codex 重建 | 是，可回到恢复前快照 |
| 单条会话删除 | 目标 writer lock、rollout 指纹、SQLite 行、索引哈希、计划令牌 | rollout/SQLite/索引/分页历史备份 | 文件恢复 + SQLite 事务回滚；投影由 Codex 重建 | 有完整删除备份时是 |
| 批量会话删除 | 同上，最多 500 个 ID | 一份批量备份 | 已删除 rollout/索引恢复 + 事务回滚；投影由 Codex 重建 | 有完整批量备份时是 |
| 删除备份恢复 | 目标 writer lock、目标冲突、SQLite/索引状态、计划令牌 | 恢复安全点及分页历史备份 | 删除新写文件、恢复索引、事务回滚；投影由 Codex 重建 | 历史中不再嵌套开放 |
| 可见性修复 | rollout/SQLite 供应商状态、计划令牌 | SQLite 与待改 rollout 备份 | 文件恢复 + SQLite 事务回滚 | 是，恢复统一前供应商字段 |
| 会话快照恢复 | 目标 writer lock、目标指纹、SQLite/索引状态、计划令牌 | 恢复安全点及分页历史备份 | 文件/索引恢复 + 事务回滚；投影由 Codex 重建 | 历史中不再嵌套开放 |
| 可见性备份恢复 | 当前供应商字段、目标存在性、计划令牌 | SQLite 与待改 rollout 当前安全点 | 仅回退清单中的供应商字段；失败时文件恢复 + SQLite 事务回滚 | 历史中不再嵌套开放 |
| 永久删除备份 | 备份 ID、manifest、根目录与文件类型校验 | 无 | 无 | 否 |
| Claude 单条/批量会话删除 | 会话包逐文件指纹、索引指纹、计划令牌 | 完整会话包与原索引 | 复制回全部已删数据并恢复索引 | 是，可从删除备份恢复 |
| Claude 删除备份恢复 | 备份指纹、目标冲突、索引状态、计划令牌 | 只写入缺失目标，不覆盖不同内容 | 移除本次新写目标并恢复索引 | 历史中不嵌套开放 |
| Claude 轮次删除 | 主 JSONL SHA-256（sourceHash） | 主 JSONL、该轮 tool-results 文件与子代理 JSONL/meta | 写回主 JSONL 并复制回全部外置产物 | 是，从轮次删除备份恢复 |
| Codex 项目路径迁移 | rollout/SQLite/索引指纹、计划令牌、Codex 进程检测 | 待改 rollout、SQLite 与索引备份 | 文件恢复 + SQLite 事务回滚 | 是，恢复旧项目路径 |
| Claude 项目路径迁移 | 主 JSONL/项目索引指纹、目标冲突、计划令牌 | 待迁移主 JSONL 与新旧索引备份 | 主文件与侧边目录移回旧项目存储并恢复索引 | 是，恢复旧项目路径 |

“历史中不再嵌套开放”表示恢复操作仍有安全点，可在备份管理中检查，但不会让一键撤销形成不清晰的无限恢复链。

## 原子文件写入与 SQLite

rollout 和索引文件通过同目录临时文件写入后再替换，避免进程中途退出留下半行 JSONL。写入完成后会重新读取并解析 JSONL。

SQLite 多行修改使用 `BEGIN IMMEDIATE` 事务；预期修改行数不一致会立即失败。工具不会为了恢复一个线程而用旧数据库覆盖整个当前数据库，而是验证并插入或更新指定线程。

可见性回退同样不会把 Codex 整体恢复到备份时间。工具仅处理原修复清单中的会话：重写 rollout 的 `session_meta.model_provider`，并用带当前值条件的 SQLite 更新恢复 `threads.model_provider`。备份后新增的会话、rollout 后续消息以及 SQLite 其他列不参与回退。修复时补回的 rollout 会保留文件和后来消息，只回退供应商字段。任何目标缺失或供应商值发生第三方变化都会成为冲突，并在写入前禁止整批回退。

Codex 的 `thread_history_N.sqlite` 是从 rollout 生成的分页读取投影。涉及目标会话正文的写操作会先用 SQLite 在线备份保存数据库，在源文件或主 SQLite 修改并验证成功后，再在事务中仅删除目标 `thread_id` 的 `thread_items`、`thread_turns` 和 `thread_history_projection_state` 行。这个顺序防止其他仍运行的 Codex 进程在写入间隙重新物化旧正文。其他会话的投影不变；目标会话下次打开时由 Codex 从当前 rollout 重建。

## Codex 运行时

- 读取、诊断和预览始终允许。
- 消息编辑、轮次清理、整会话删除、会话删除备份恢复和轮次快照恢复只要求关闭目标会话。其他 Codex 窗口可以继续运行。
- 预览会探测 `%CODEX_HOME%\thread-writer-locks\<session-id>.lock` 的实际字节区间锁，而不是仅判断锁文件是否存在。写入时工具持有同一目标锁；目标在预览后被重新打开时，操作会拒绝执行。
- 写入完成后重新打开目标会话，Codex 会从当前 rollout 重建分页历史。无需关闭或重启其他 Codex 窗口。
- 可见性修复、项目路径迁移及其回退要求 Codex 完全退出，防止 Codex 用内存中的旧状态覆盖修改结果。
- 一键撤销沿用被调用恢复模块的规则，不绕过运行中检查。

## 操作历史的安全边界

历史保存在普通备份根目录的 `operation-history.jsonl`。它记录操作类型、时间、状态、会话 ID、有限结果摘要和恢复描述，不记录请求正文、消息内容、密钥或授权字段。疑似敏感字段会被清理，长字符串会截断。

每个操作同时满足以下条件时都可以在对应历史记录旁回退：

1. 状态为已完成；
2. 没有被撤销；
3. 完成事件包含受支持的恢复点；
4. 当前文件、索引或数据库字段仍与该操作完成时一致，没有发生冲突。

点击撤销时仍会验证当前文件哈希、备份存在性、目标冲突和 Codex 运行状态。失败不会强制覆盖后来发生的修改。

## 永久删除

永久删除只接受枚举接口返回的备份 ID。服务端再次确认目标位于预期根目录、带合法清单、是普通目录且不是符号链接。它不会接受任意绝对路径，也不会递归删除 `.codex`、备份根目录或 CCSwitch 数据。
